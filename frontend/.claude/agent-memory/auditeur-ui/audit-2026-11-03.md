Audit Analyse/Audit réalisé en lecture seule le 2026-11-03 sur la refonte clair/sombre.

- L'application force actuellement le mode sombre (`ThemeProvider defaultTheme="dark"`, `switchable=false`) et `index.css` ne définit qu'une palette sombre dans `:root, .dark`.
- Le backend renvoie 4 niveaux de sévérité (`normal`, `warning`, `critique`, `tres_critique`), alors que la SPEC n'en prévoit que 3 à l'affichage.
- Décisions en attente de l'utilisateur : mapping 4→3 des sévérités, et inclusion ou non de `AlertFeed` (console dashboard) et de `NetworkLogs` (sans colonne sévérité) dans le périmètre « logs » de la SPEC.

**Why:** ces deux points conditionnent le hook `useLogsDisplay`, le type partagé et la phase 6 du PLAN.
**How to apply:** ne pas trancher unilatéralement ; poser la question ciblée avant d'écrire le code de la phase logs. Voir [[projet-sentinedog]].
